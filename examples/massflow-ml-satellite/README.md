# massflow-ml satellite — reference implementation

A minimal, self-contained example of a `massflow-ml` satellite server that
fulfills the `massflow.v1.ml` wire contract consumed by the MassFlow core
(see `MassFlow.ml_client.RemoteMLEngine` and `protos/massflow/v1/ml.proto`).

The satellite demonstrates the decoupled ML architecture: the MassFlow core
contains **no** PyTorch/Gensim dependencies; heavy scoring engines live
behind the `MLEngineProtocol` boundary and are reached over REST or gRPC,
with a circuit breaker and classical fallbacks on the client side.

## What is in here

| File | Purpose |
| --- | --- |
| `dummy_model.py` | A lightweight binned-cosine scoring model with a `load(path)` entry point (the "model weights" are the binning hyperparameters in `model.json`). Swap this for a real Spec2Vec / MS2DeepScore model. |
| `model.json` | Dummy model file loaded at server start. |
| `rest_server.py` | FastAPI implementation of the REST transport: `POST /{algorithm}/search` and `POST /{algorithm}/batch_score` + `GET /health`. |
| `grpc_server.py` | gRPC implementation of `MLEngineService` (`Search` / `BatchScore`) using the stubs generated by `scripts/protoc_gen.sh`. |
| `client_smoke.py` | End-to-end demo: boots both transports and drives them through the core's own `RemoteMLEngine` client. |
| `requirements.txt` | Standalone dependencies for the satellite process. |

## Run it

From the repository root (massflow installed in the environment):

```shell
# 1. Install the satellite-only dependencies (fastapi, uvicorn, httpx).
uv pip install -r examples/massflow-ml-satellite/requirements.txt

# 2. Start the REST transport on :8080.
uv run uvicorn rest_server:app --app-dir examples/massflow-ml-satellite \
    --host 0.0.0.0 --port 8080

# 3. Start the gRPC transport on :9090.
uv run python examples/massflow-ml-satellite/grpc_server.py --port 9090

# 4. Point the MassFlow core at the satellite in your config:
#    similarity:
#      ml_endpoints:
#        spec2vec: "http://localhost:8080/spec2vec"
#        ms2deepscore: "grpc://localhost:9090"

# 5. Or run the bundled end-to-end smoke demo (starts both transports
#    in-process and drives them with RemoteMLEngine):
uv run python examples/massflow-ml-satellite/client_smoke.py
```

## The contract in one glance

A search request carries the algorithm name, float64 query spectra, and
float64 reference spectra; the response returns per-query ranked hits in the
same shape the core's `SearchResult` dictionaries use:

```jsonc
POST /spec2vec/search
{
  "algorithm": "spec2vec",
  "query_spectra": [
    {"spectrum_id": "q1", "mz_array": [100.0, 200.0],
     "intensity_array": [0.5, 1.0], "metadata": {"precursor_mz": "300.0"}}
  ],
  "reference_spectra": [ /* ... */ ],
  "min_score": 0.0,
  "top_n": 5,
  "include_decoys": false
}
// -> {"results": [{"query_id": "q1", "hits": [{"reference_id": ...,
//     "score": 0.9, "matched_peaks": 3, ...}]}]}
```

A standalone satellite repository should copy `protos/massflow/v1/ml.proto`
and generate its own stubs; this example imports the in-repo generated
stubs for convenience.

## Extending with real models

1. Implement `search(query_spectra, reference_spectra, ...)` in
   `dummy_model.py` behind the same signature, replacing the binned-cosine
   with Spec2Vec embeddings or an MS2DeepScore Siamese network.
2. Put real weights in a model file and load it in `load()`.
3. The wire contract, the FastAPI routes, and the gRPC servicer stay
   unchanged — that stability is the point of the boundary.
