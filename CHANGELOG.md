# CHANGELOG

## v 0.8.0

**Summary:**
Major update focusing on statistical validity, memory management, and scaling. Resolved critical Out-Of-Memory (OOM) issues in the multiprocessing pipeline and implemented a statistically robust Global False Discovery Rate (FDR) calculation.

**Features & Improvements:**

- **Memory-Safe Multiprocessing**: Resolved OOM crashes caused by duplicating large reference libraries across worker processes. Implemented a memory-safe worker initialization strategy using SQLite database caching for zero-copy reads via `io.load_spectra`.
- **Global FDR Calculation**: Fixed a major statistical flaw where FDR (q-values) were calculated locally per chunk. FDR computation is now centralized in the main process (`workflow.py`) after all searches complete, ensuring q-values are calculated against the true global score distribution.
- **Robust Decoy Generation**: Redesigned decoy spectrum generation for Machine Learning algorithms (Spec2Vec, MS2DeepScore). Decoys are now generated by shuffling *intensities* rather than shifting *m/z* values. This ensures `matchms.Spectrum` compliance (monotonically increasing m/z arrays) and produces statistically valid null distributions.
- **Streamlined Search Pipeline**: Scoped down `engine.search()` in `similarity.py` to handle only score computation and base filtering (`min_score`, `min_matched_peaks`). Global sorting, Top-N filtering, and FDR application are now cleanly handled by the workflow orchestrator.

## v 0.7.0

**Summary:**
Major compliance update to align with the v1.0 High-Level Design (HLD). Introduced dynamic algorithm switching, integrated the pre-processing pipeline, and enforced strict configuration validation for spectral filtering.

**Features & Improvements:**

- **Pre-Processing Pipeline**: Fully integrated `processing.py` into the workflow. Spectra are now automatically sanitized (metadata) and filtered (peaks) before matching.
- **New Filters**: Implemented `select_by_mz` (range truncation) and `reduce_to_number_of_peaks` (Top-N) to optimize matrix density.
- **Algorithm Switching**: Added support for `ModifiedCosine` alongside `CosineGreedy`. The engine now dynamically instantiates the algorithm based on `config.similarity.algorithm`.
- **Config-First Architecture**: Refactored CLI to require a YAML configuration file (`--config`). Removed loose command-line arguments to ensure reproducibility.
- **Strict Validation**: Updated Pydantic schema in `config.py` to enforce physical constraints on pre-processing parameters (e.g., `mz_to > mz_from`).

**Testing:**
- Added integration tests for mass-shifted analogues to verify `ModifiedCosine` functionality.

## v 0.6.0

**Summary:**
Architectural refactor of the `MassFlow` core. Transitioned from a script-based workflow to a modular system with Strategy/Facade design patterns, strict type safety, and robust configuration validation.

**Architectural Changes:**

- **Hub-and-Spoke Architecture:** Implemented a centralized `workflow.py` orchestrator that coordinates specialized modules.
- **Strategy Pattern (Similarity)**: Decoupled similarity algorithms from the workflow. `Cosine` and `ModifiedCosine` are now interchangeable strategies in `similarity.py`.
- **Facade Pattern (Processing)**: Encapsulated `matchms` filtering logic behind a simplified, strict interface in `processing.py`.
- **Pydantic Configuration**: Replaced raw dictionary config handling with strict Pydantic models in `config.py`. Mass spec parameters (m/z, RT) are now validated for physical correctness (e.g., non-negative values).

**Code Quality & Standards:**

- **Unified I/O**: Consolidated all loading/saving logic into `io.py`, removing legacy Pandas dependencies and harmonizing file access via `pathlib.Path`.
- **Type Safety**: Enforced Python 3.10+ strict type hinting across all modules.
- **Documentation**: Added `ARCHITECTURE.md` with Mermaid.js diagrams to document system flow.
- **Google-Style Docstrings**: Standardized docstrings for all classes and functions.

**Breaking Changes:**

- **Config Schema**: The YAML configuration structure has changed to align with the new Pydantic models. Old config files will require updates.
- **API**: `processing.clean_msp_library` and other standalone script functions have been removed in favor of the pipeline approach.
