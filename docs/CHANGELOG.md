# Changelog

All notable changes to MassFlow will be documented in this file.

## [Unreleased]
### Added
- **Annotation-run seed wiring for network context (P6.1, EXPERIMENTAL, post-1.0):** `MassFlow.network.context.seeds_from_results` projects the annotation pipeline's `FileExecutionResult`s into `AnnotationSeed`s (the best hit per query node; content-addressed node ids; `calibrated=False` when the run was `fdr_uncalibrated`, so uncalibrated q-values can never seed context). `massflow network analyse --config ...` now runs the annotation pipeline and seeds L5 `NetworkContext` / `AnnotationInference` records end-to-end. New user guide: `docs/user-guide/network.md`.
- **Molecular families, export & MSMCP (P6, EXPERIMENTAL, post-1.0):** `MassFlow.network.families.detect_families` produces deterministic `MolecularFamily` records (content-addressed `family_id`, member/edge ids, and an inherited label + seed ids when an L5 `NetworkContext` exists); `build_spectral_graph` attaches families by default (`NetworkConfig.build_families`). `MolecularGraph` gains a validated `families` field and `to_family_jsonl()`, and `MassFlow.io.save_families_jsonl` exports families. `MassFlow.network.msmcp.LocalGraphSource` provides a **dependency-free, offline, read-only** MCP-style interface (`list_resources` / `read`) over nodes, edges, families, inferences and provenance, with statistical confidence exposed **only** through `annotations()` (sourced from `FdrAssessment`). New CLI: `massflow network analyse` (attach families to a graph JSON) and `massflow network export` (families JSONL). A networked MCP server is deferred (optional extra); `LocalGraphSource` is fully usable offline. Tests: `tests/test_network_families.py`, `tests/test_network_msmcp.py`, `tests/test_network_cli.py`.
- **Annotation contextualization (P5, EXPERIMENTAL, post-1.0):** `MassFlow.network.context.contextualize` derives **L5** family context and network-inferred annotations from direct, calibrated seed annotations (`AnnotationSeed`). New data-layer types `NetworkContext` (descriptive label, `label_source`, member ids, seed ids) and `AnnotationInference` (`status="network_inferred"`, supporting seed ids, incident edge ids) carry **no** q-value/score/tier; `MolecularGraph` gains `network_contexts`/`inferences`, validated so members must exist, inferences must target query nodes and reference a known context, and inference targets must be distinct. Anti-circularity is structural: only calibrated seeds with `q_value <= context_seed_q_threshold` seed a component; inference is computed **solely** from direct seeds (never from other inferences); the graph's `FdrAssessment` set is never read, written or re-derived; and `apply_context` rebuilds (re-validating) rather than mutating. The deterministic connected-components primitive (`MassFlow.network.families`) is pulled forward from P6 as a prerequisite for this stage. New config: `NetworkConfig.build_context`, `context_seed_q_threshold`. Tests: `tests/test_network_context.py`.
- **Chemical relationships (P4, EXPERIMENTAL, post-1.0):** `MassFlow.network.chemical.build_chemical_relationships` hypothesizes neutral-loss relationships between LC-MS features by matching the adduct-resolved neutral-mass difference against a curated table of common fragmentations (`NEUTRAL_LOSSES`: H2O, NH3, CO, CO2, CH2O, CH2, CH4, C2H2, C2H4, HCN, H2S, SO2, SO3, O, HCl, anhydrohexose, hexose), with fragment masses from `pyteomics`. Every edge is an explicit `interpretation_status="hypothesis"` / `molecule_relationship="related_molecule"` carrying a `NeutralLoss` (observed mass + ppm error) — **never** a structural claim. Multiply-charged adducts are handled correctly (the comparison uses neutral masses, not precursor m/z). Unresolvable adducts and cross-ionisation-mode pairs fail closed; an uninterpretable Δmass yields no edge. New config: `NetworkConfig.build_chemical`, `chemical_ppm_tolerance`. Tests: `tests/test_network_chemical.py`. (`ChemicalRelationship.delta_mass_da` is now documented as the adduct-resolved neutral-mass difference.)
- **Ion-identity relationships (P3, EXPERIMENTAL, post-1.0):** `MassFlow.network.ion_identity.build_ion_identity_relationships` links LC-MS features that are the **same molecule** observed as different adducts, by deriving each feature's neutral mass from its precursor m/z and its registered adduct offset (`cheminformatics.compute_adduct_offset`) and requiring agreement within `ion_identity_ppm_tolerance` (default 5 ppm — distinct from the mandated 5 ppm precursor *validation* gate). Emits `IonIdentityRelationship(relationship_kind="adduct", molecule_relationship="same_molecule")`; unregistered adducts, declared-charge contradictions and cross-ionisation-mode pairs **fail closed** (no mass is guessed, no structural claim is made). `build_spectral_graph` now adds these feature-level edges by default (`NetworkConfig.build_ion_identity`). Isotope, in-source-fragment, and multimer discovery are deferred. Tests: `tests/test_network_ion_identity.py`.
- **R-1 fixed — candidate-driven spectral scoring (P1 hardening):** Stage 1 scoring no longer materializes an `O(N²)` similarity matrix. Each unordered candidate pair is scored exactly once via a bounded single-query search, so peak memory is `O(max candidate degree)`; edge results are unchanged. Verified by `tests/test_network_build.py::test_scoring_is_bounded_by_candidate_degree`.
- **Feature-based networking (P2, EXPERIMENTAL, post-1.0):** `MassFlow.network.features.build_features` groups experimental spectra into deterministic LC-MS features — partitioned by ion channel `(ion_mode, charge, adduct)` and clustered with single-linkage over the reused MS1/RT candidate generator (`feature_precursor_tolerance`, `feature_rt_tolerance`). The representative is the highest-TIC member (deterministic node-id tie-break); membership is stamped onto each (frozen) `GraphNode.feature_id` and the `Feature` objects are attached to the `MolecularGraph`. `build_spectral_graph` now builds features by default within an enabled network; a missing retention time does not block m/z-consistent grouping. Purely additive: nodes, edges, and all confidence invariants are unchanged. New config fields: `NetworkConfig.build_features`, `feature_precursor_tolerance`, `feature_rt_tolerance`. Tests: `tests/test_network_features.py`.
- **Spectral networking (P1, EXPERIMENTAL, post-1.0):** `MassFlow.network` is now a package. Stage-1 (spectral) networking is implemented deterministically: `MassFlow.network.candidates.generate_candidate_pairs` (MS1/RT window candidacy), `MassFlow.network.spectral.build_spectral_relationships` (classical cosine/modified-cosine edges through the existing `SimilarityEngine` with `include_decoys=False` — decoys are an annotation-only FDR device), and `MassFlow.network.build.build_spectral_graph` (spectra → data-only `MolecularGraph`). Adds an opt-in, **disabled-by-default** `network:` config section (`MassFlow.config.NetworkConfig`) and the experimental `massflow network build --config ... [--output ...]` command, which writes `<input_stem>_network.json` via `MassFlow.io.save_molecular_graph`. Nodes and edges use hash-seed-independent, content-addressed identifiers, so repeat runs are identical. Confidence discipline is preserved: networking never reads or writes q-values/FDR (no edge can carry confidence; graphs ship `fdr_assessments: {}`), input spectra are never mutated (they are scored via clones), and the stable path still never imports `MassFlow.network`. Tests: `tests/test_network_{candidates,build,config,cli}.py` plus the data-layer suite; design: `docs/network-aware-annotation-spec.md` §6/§11.
- **Graph-compatible data layer (`MassFlow.network`, graph-compatible v1.0):** a new, strictly-downstream data module defines the typed vocabulary for future *Network-Aware MS Annotation* without changing the annotation workflow. It adds deterministic content-addressed identifiers (`spectrum_node_id`/`library_node_id`/`feature_node_id`/`relationship_id`, `SHA-256`-based and `PYTHONHASHSEED`-independent), metadata-projection nodes (`GraphNode`, `Feature`), **layered evidence** (`AnnotationEvidence` for L1 direct identification evidence and a separate query-scoped `FdrAssessment` for L2 primary statistical confidence — the only FDR carrier), typed edges (`SpectralRelationship`, `ChemicalRelationship`, `IonIdentityRelationship`, unified as the discriminated `Relationship`; each separates "same molecule" from "related molecule" and treats chemical edits as explicit hypotheses), per-edge provenance (`RelationshipProvenance`) and a data-only, lossless-JSON container (`MolecularGraph`) with file I/O in `MassFlow.io.save_molecular_graph`/`load_molecular_graph`. Invariants are enforced structurally: no edge can carry `q_value`/`p_value`/`fdr`/`confidence`, FDR semantics are unchanged, missing values are `null` (not `0`/`NaN`), float64 precision and `retention_time_seconds` units are preserved, and nothing on the stable path imports the module. This ships **data types only** — no networking, clustering, FBMN, GraphML, or visualization. Tests: `tests/test_network_{ids,models,serialization,invariants,isolation}.py`; docs: `docs/network-data-model.md`.
- **Frozen design spec for Network-Aware MS Annotation (post-1.0, not shipped):** `docs/network-aware-annotation-spec.md` freezes the design for the future networking subsystem built on the graph data layer — spectral, feature-based, ion-identity, and chemical networking stages; non-circular annotation contextualization; deterministic molecular-family analysis; a local-first MSMCP machine interface; explicit classical-vs-ML delegation; and binding confidence-governance invariants (network context never alters q-value/FDR). It ships no capability and is subordinate to `docs/CAPABILITY_MATRIX.md`.
- **`massflow tutorial` CLI command:** First-class command that generates a self-contained synthetic dataset (reference library, experimental queries, and pre-configured YAML) for instant local evaluation. No external files required.
- **Enhanced tutorial generator:** `scripts/generate_tutorial_data.py` now prints formatted next-steps with the exact `db build` and `annotate` commands to run after generation.
- **Hybrid SQLite + Zarr storage (Phase 1):** `SpectralDatabase` now supports a hybrid mode (`zarr_path=...` or `--backend hybrid`) where SQLite retains metadata plus a `zarr_ref`/`zarr_index` reference pair and fragment arrays live in a chunked, compressed `ZarrPeakArrayStore` with lock-free concurrent reads for multiprocessing.
- **BLOB → Zarr migration:** `scripts/migrations/0002_blobs_to_zarr.py` (wrapping `MassFlow.database.migrate_blobs_to_zarr`) migrates existing SQLite BLOB libraries to the hybrid backend with per-batch bitwise verification, idempotent re-runs, and orphaned-array recovery.
- **Algorithmic acceleration (Phase 2):** Numba-accelerated peak/neutral-loss prefilter (`MassFlow.acceleration`) that skips query-reference pairs below `min_matched_peaks` before exact modified-cosine scoring, with identical results and a pure-NumPy fallback.
- **HNSW candidate retrieval (Phase 2):** `MassFlow.hnsw` wraps hnswlib for sub-linear approximate candidate generation over binned spectral vectors, integrated into `CascadeEngine` as an optional pre-stage. Construction parameters (`hnsw_m`, `hnsw_ef_construction`, `hnsw_ef_search`, `hnsw_candidates_per_query`, binning) are exposed in `SimilarityConfig` with recall-friendly defaults because spectral similarity is non-metric. Requires the new `[hnsw]` extra.
- **Entropy-based decoy generation (Phase 3):** `generate_decoys` now produces entropy-preserving decoys that keep the precursor m/z and the Shannon entropy (ion information content) of each target while randomizing fragmentation pathways via intensity permutation and fragment-position jitter, replacing naive fragment shuffling. `ProcessingConfig` gains `decoy_min_relative_intensity` (strict baseline noise filtering before entropy computation) and `decoy_mz_shift_da`; the workflow logs a target-decoy entropy-divergence diagnostic for FDR calibration.
- **Real-time streaming hardening (Phase 4):** the gRPC `StreamSpectra` path now routes every packet through the `ConsensusEngine` (weighted multi-engine scoring) and enforces quality-gated backpressure: when the bounded queue reaches a configurable high-water mark, low-quality spectra are shed (reported via the new `ServerStatus.spectra_dropped_low_quality` field) to prevent memory exhaustion and latency collapse under instrument overrun. `massflow serve` gains `--queue-high-water-mark` and `--queue-low-quality-threshold`; `GetStatus` now also reports rolling processing latency.
- **ML API boundary (Phase 5):** external ML scoring is now fully decoupled behind `MLEngineProtocol`: `SimilarityConfig.ml_endpoints` routes Spec2Vec/MS2DeepScore scoring to remote REST (`http(s)://`) or gRPC (`grpc://`, the new `massflow.v1.ml` service) services via a `CircuitBreaker`-protected `RemoteMLEngine` client (no heavy dependencies required in core). `ConsensusEngine`, `CascadeEngine`, `MLRouter`, and the workflow now degrade gracefully to modified_cosine + empirical p-values when the ML service is unreachable or PyTorch/Gensim are missing.
- **Audit fix — HNSW neutral-loss channel:** `spectrum_to_binned_vector` now encodes a 2-channel concatenated vector `[binned exact m/z, binned neutral losses]`, so HNSW candidate retrieval can find precursor-shifted analogues (modified-cosine matches with disjoint exact m/z) that an exact-m/z-only index was blind to. `bin_spectra` and `HNSWSpectralIndex` dimensionality updated accordingly.
- **Audit fix — spectral entropy physics:** `spectral_entropy` and the decoy generator now apply the spectral-entropy `I**0.5` weighting and a hard baseline filter (peaks below `decoy_min_relative_intensity` × the **base peak**, default 1%) before computing the information content, preventing chemical noise from inflating entropy and biasing FDR calibration.
- **Golden scientific-validation suite:** `tests/test_scientific_validation.py` locks down the scientific contract end-to-end with known-answer assertions — perfect and near spectral matches (hand-computed cosine), precursor-mass and adduct violations, RT-tolerance filtering, deterministic entropy-preserving decoys, the per-query target-decoy FDR contract, duplicate-score ranking, large-peak-count round trips, and SQLite/Zarr storage equivalence (byte-identical result CSVs). The known-answer fixture set is produced deterministically by `tests/scientific_validation/generate_ground_truth.py` (the previously committed static MGF fixtures were removed); the suite runs in the default test selection under the `scientific` marker and explicitly in CI. See `docs/user-guide/scientific_validation.md`.
- **Terminal console (`massflow tui`):** a keyboard-first interactive console for finding, uploading, viewing, and identifying MS/MS data without leaving the terminal. Four tabs — **Browser** (recursive spectral-file discovery, vendor-format conversion hints, collision-safe upload into a workspace directory, library inspector), **Viewer** (interactive centroid stick plot with precursor marker; metadata panel with precursor m/z, RT, charge, adduct, base peak, TIC, spectral entropy), **Identify** (target-decoy search with q-value/p-value calibration, ranked hits, mirror plots), and **Diagnostics** (plain-English fixes plus the `massflow_quarantine.log` tail). New options `--input`, `--library`, `--workspace` (default `./massflow_workspace`); requires the new `[tui]` extra (`textual>=8`). Experimental — outside the stable product contract. See `docs/api/tui.md` and `tests/test_tui_*.py`.
- **Physical-integrity gate in the classical annotation paths (D-8 executed, see `docs/CAPABILITY_MATRIX.md`):** `MassFlow.processing` now runs the existing `SpectrumMetadata`/`MolecularStructure` 5 ppm contracts (`MassFlow.models`) on every spectrum that declares a structural claim (formula/SMILES/InChI) after `matchms` harmonization, via `processing.physical_integrity_reason` (wired into `process_spectra`/`process_spectra_batch` with an optional rejection reporter). Malformed structural metadata (unparseable formula/SMILES/InChI claims, formula/exact-mass conflicts beyond 5 ppm, non-registry adducts in a complete context) and **>5 ppm precursor deviations** are rejected with human-readable reasons, quarantine-logged, and never searched. Spectra without structural claims are exempt (raw experimental files pay no measurable cost; envelope auto-fill is suppressed in the gate — it is not consumed by the classical path). Semantics: **query files** count rejections in `spectra_rejected` with reasons surfaced in the failure report when the file fails; **raw reference libraries** abort `annotate`/`watch` with `processing.PhysicalIntegrityError` before any file is processed (a silently shrunk pool would corrupt every query's FDR calibration) and the partial store is removed; `db build` quarantines invalid entries (curation workflow). `massflow annotate` prints run-level failures to the console. Tests: `tests/test_physics_gate.py`; docs updated (`docs/user-guide/validation.md`, `docs/user-guide/data-requirements.md`, `docs/ARCHITECTURE.md`, `docs/index.md`).
- **Library-build provenance (lineage schema):** SQLite-backed stores now persist a lightweight lineage history — `store_meta` (schema version, first-open timestamp) and `library_builds` (`PRAGMA user_version` >= 1). Every `db build`, `db merge`, and annotate library-store build records the input file(s) used with a streaming SHA-256, the effective config hash (`config_digest_sha256`), the processing fingerprint, full processing and similarity (target-decoy) configuration JSON, the MassFlow version, and an exact UTC timestamp; merges additionally list their input databases and per-input spectrum counts in `details.merged_sources`. The schema is additive and idempotent raw SQL (pre-provenance databases self-upgrade on their next open; scientific payload bytes are untouched; Zarr stores are not modified). `massflow db inspect` is now a lineage query surface: it reports store metadata, the full build history (library versions), the recorded processing parameters, and the target-decoy configuration. The `annotate` YAML sidecar gains a `library:` block linking every result to the exact store searched and its `library_builds` row (build id, built-at timestamp, source file, config digest, processing fingerprint) so run config can be checked against build config. Programmatic access: `SpectralDatabase.record_library_build` / `get_library_builds` / `get_latest_library_build` / `get_schema_version` / `get_store_created_at`; `MassFlow.library.processing_fingerprint` is now public. Tests: `tests/test_db_lineage.py`. Docs: `docs/user-guide/database.md`, `docs/user-guide/results.md`, `docs/ARCHITECTURE.md`.
- **Pre-flight validation (fail fast before any expensive work):** `massflow annotate`, `db build`, and `db merge` now validate their inputs before any library store is built or any file is searched. `MassFlow.workflow.preflight_annotation_run` (wired into `run_annotation_pipeline` before the output directory is even created) checks, in order: (1) the configured similarity surface can be constructed with the installed optional extras — a pure ML engine such as `spec2vec` without `massflow[ml]` aborts here with the install instruction instead of crashing workers as an opaque `BrokenProcessPool` after the store build; (2) the reference library is configured, exists, and is a loadable open-format/store input — vendor raw libraries and unknown formats abort before any temporary store is created; (3) the query input exists and is dispatchable — a direct vendor file/`.d` input aborts up-front, while vendor files *inside* a directory are announced at run start and keep the documented explicit per-file failure semantics. Missing optional extras that degrade instead of abort (`consensus`/`cascade` without `[ml]`, `cascade` + `hnsw_enabled: true` without `[hnsw]`) are emitted as run-start warnings carrying the `pip install massflow[...]` fix (`MassFlow.workflow.optional_extra_warnings`). `db build` rejects vendor/unloadable sources and `db merge` rejects missing or non-store inputs before the output database file is created (previously an empty `.db` was left behind). CLI failures now print a plain-English `fix:` hint line via `MassFlow.tui.diagnostics.suggest_fix` (new HNSW branch) instead of a bare error; no failing run leaves output artifacts. Single-source-of-truth loadability helpers `io.is_vendor_raw` / `io.is_loadable_spectral_input` / `io.is_store_input` (with a canonical vendor error message) back both the loader and the pre-flight checks. Tests: `tests/test_preflight.py`; README gains a documented "happy path" (input → library build → annotation → export → inspect). Docs: `docs/user-guide/annotation.md` (Pre-flight validation + tightened vendor handling), `docs/CAPABILITY_MATRIX.md`.
- **Adduct registry expansion & notation normalisation (issue #72):** `MassFlow.cheminformatics` now recognises the adducts that dominate real library exports and resolves the many ways a file may spell them. New registry entries: positive mode `[M+3H]3+`, `[M+2Na-H]+`, `[M+H-H2O]+`, `[M+CH3CN+H]+`, `[M+CH3OH+H]+`; negative mode `[M-2H]2-`, `[M+Br]-`, `[M+I]-`, `[M+TFA-H]-`, `[M+HCO3]-`, `[M+NO3]-`. The new public `cheminformatics.normalize_adduct` canonicalises notation variants (`M+H`, `M+Na`, `[M+H]1+`, `[M+H]+1`, `[m+h]+`, interior whitespace, unbalanced brackets, and alias chemistry such as `M+FA-H`, `M+OAc`, `M+ACN+H`, `M-H2O+H`) onto the registry keys. Normalisation fails **closed**: a notation whose declared charge contradicts the chemistry (`[M+H]2+`), a charge-less ambiguous body (`M`), or chemistry outside the registry (`[M+Weird]+`) still resolves to `None` and is still rejected by the gate. `compute_adduct_offset` and `calculate_theoretical_mass` accept the same variants, and `SpectrumMetadata` stores the canonical spelling while `metadata_processing` canonicalises it during ingestion, so the physics gate, database columns, triage, and exports all agree on one form. Notably, normalisation cannot manufacture false positives — a resolved adduct must still clear the 5 ppm precursor gate. Tests: `tests/test_adduct_registry.py`; docs: `docs/user-guide/validation.md`, `docs/user-guide/data-requirements.md`, `docs/ARCHITECTURE.md`.

### Changed
- **Developer tooling — CI parity and pre-commit scope:** the local `Makefile` gains a `make ci` target that mirrors the full remote pipeline (lockfile check, lint/format/type checks, the release suite with coverage, the explicit `scientific` and `optional` groups, a self-generating end-to-end smoke run, and `mkdocs build --strict`), so the pre-push gate can match CI exactly. The `mirrors-mypy` `pre-commit` hook was **removed**: it ran in an isolated, dependency-sparse environment whose third-party types differ from the project's, so its verdict could diverge from the real `mypy .` gate; type checking stays a `make`/CI concern. CI's `lockfile-and-lint` job now also runs `mkdocs build --strict` so stale documentation fails the build like any other check. See `CONTRIBUTING.md` § Tests (Type checking).
- **Developer tooling — full-repo type checking by default:** `make typecheck` now documents that it runs `mypy .` over `src/` **and** `tests/` (the same scope as CI), and a new `make typecheck-src` target is a clearly-labelled, **partial** src-only fast check that prints a reminder to run the full gate before pushing. A new `make static` target runs lint + format-check + the full type check (no tests). `CONTRIBUTING.md` documents the three targets so a partial check can never be mistaken for the gate.
- **Annotate input discovery includes `.baf` (vendor-format tightening):** directory discovery now derives its vendor extension set from `io.PROPRIETARY_FORMATS` (which includes Bruker `.baf`), so a `.baf` file inside an input directory produces an explicit per-file `failed` result like every other vendor raw format instead of being silently ignored. Vendor handling is documented in `docs/user-guide/annotation.md`.
- **Strict configuration validation (config audit):** all Pydantic configuration models now reject unknown keys (`extra="forbid"`) — a misspelled key such as `ms2_tolerence` fails immediately with a human-readable error carrying the YAML line number, a spelling suggestion (when one is close), and the allowed keys. Relative paths (`project.output_directory`, `input.input_path`, `input.library_path`) now resolve **relative to the YAML configuration file's directory** instead of the caller's working directory, making runs deterministic regardless of the invocation CWD; the legacy CWD-relative behavior is available via the documented `MASSFLOW_COMPAT_CWD_PATHS=1` environment variable. Invalid combinations now fail at validation time instead of silently doing nothing: `hnsw_enabled` requires `algorithm='cascade'`, `reduce_to_top_n_peaks` requires a positive `n_max`, `cascade_stages`/`consensus_weights` must reference leaf engines with positive weights, and `cascade_upper_bound >= cascade_lower_bound`. The batch processing path now honors the documented `filter_min_peaks` / `filter_by_mz` toggles (it previously dropped spectra by `min_peaks`/precursor `mz_max` even when the toggles were off). A normalized configuration representation (schema version, source config path, full effective config with resolved paths, SHA-256 digest) is written into provenance: a run-level `run_provenance.json` in the output directory before expensive processing, plus a `config:` section in every per-file report sidecar. See `docs/user-guide/configuration.md` and `tests/test_config_strictness.py`.
- **Failure model (per-file execution results):** every experimental input file now produces a structured `FileExecutionResult` (status `success`/`degraded`/`failed`, input path, spectra loaded, spectra rejected, hits produced, output path, warnings, fatal errors, degraded-mode flags). A file whose data could not be loaded, validated, or scored is reported as `failed` with an explicit `<stem>_failed.report.yaml` sidecar and **no results CSV** (an empty CSV can no longer be mistaken for a successful annotation). Batch runs continue across failed files, worker crashes are synthesized into failed results, and `massflow annotate` exits nonzero when any file failed. Spectrum-level rejections (I/O validation and processing drops) are counted and recorded in the provenance; engine fallbacks (classical, consensus, cascade, routing, HNSW) and uncalibrated FDR are surfaced as `degraded_mode_flags`. Unsupported vendor formats are now explicit per-file failures with a conversion hint instead of disappearing from the batch. Cascade mid-stage failures fall back to classical scoring instead of silently returning no results. See `docs/user-guide/results.md` (Failure Model) and `tests/test_failure_model.py`.
- **Per-query target-decoy FDR contract (statistical audit):** the FDR competition unit is now the **query spectrum** — each query contributes its best target hit and its best decoy hit exactly once — instead of pooling every threshold-passing hit. Ties are ranked decoys-first (conservative). The empirical p-value is a per-query diagnostic column and is **never** used as a filter; the small-library Bonferroni branch was removed (it silently compared FWER-corrected p-values against `fdr_threshold`). The true reference-library size is now threaded through the single-file and streaming execution paths (previously derived from empty worker-local state, forcing every such run into the small-library branch). Decoy generation is chunk-invariant (content-hashed per-spectrum seeds) and honors `processing.decoy_*` in every execution mode. Cascade now scores decoys when `include_decoys=True` (previously it never did). The streaming gRPC path reports `fdr_q_value = NaN` (uncalibrated) instead of a placeholder 1.0. See `docs/user-guide/scoring_logic.md` for the full contract and `tests/test_fdr_statistics.py` for the regression suite.
- **Onboarding overhaul:** Rewrote `docs/user-guide/usage.md` to use real, runnable tutorial file paths instead of hypothetical placeholders. Added Step 0 (Generate Tutorial Data) so a copy-paste follower can complete the full workflow without `FileNotFoundError`.
- **README and ARCHITECTURE docs:** Added `massflow tutorial` to stable feature lists, CLI command references, and quickstart sections. Fixed a stray `similarity:` key in the README YAML example.
- **Config storage backends:** `input.storage_backend` now accepts `"hybrid"` in addition to `"sqlite"` and `"zarr"`; `massflow db inspect` auto-detects hybrid databases by their sibling `.zarr` store.
- **Worker-owned library backends (multiprocessing redesign):** the annotation engine no longer serializes the full processed reference library (and its decoys) into every `ProcessPoolExecutor` worker. `MassFlow.library.prepare_library` normalizes raw-format libraries into a worker-openable store in the parent (store inputs such as `.db`/`.zarr` are used directly), and only a compact `LibrarySpec` (path/kind/backend, ~185 B pickled) crosses the process boundary. Workers open the store themselves and stream processed spectra in bounded 10k-spectrum chunks, so per-worker RSS is bounded by one chunk and parent RSS is flat regardless of library size or worker count. Measured on macOS/Python 3.13 (`spawn`): 8-worker spawn wall time drops from 33–54 s to ~0.02 s at 100k spectra, with byte-identical results locked by golden CSVs asserted in `tests/test_library.py` (decoy generation remains chunk-invariant). The memory model and reproduction steps are documented in `docs/multiprocessing.md` (`scripts/benchmark_multiprocessing.py`).

### Fixed
- **Network review fixes (P1–P6 hardening):** (1) **chemical-relationship ppm prefilter corrected** — the candidate window was sized on `neutral_mass − fragment_mass` while the exact acceptance test divides by `fragment_mass`, so genuine neutral-loss relationships were silently dropped (an H₂O loss at 4.9 ppm was missed at `chemical_ppm_tolerance = 5`); the window now uses `fragment_mass` and is a strict superset of the exact check, with the tolerance's meaning and the 5 ppm precursor gate unchanged. (2) **provenance timestamps are injectable** — `RelationshipProvenance.created_at` / `GraphProvenance.created_at` are now threaded from `build_spectral_graph`, `detect_families`, `contextualize` and the new `massflow network build --created-at` / `analyse --created-at`, so a run with a fixed timestamp produces **byte-identical** graph JSON and identical relationship ids (the deterministic-identifier guarantee in `docs/network-aware-annotation-spec.md` §12 now holds end-to-end). Tests: `tests/test_network_chemical.py`, `tests/test_network_build.py`, `tests/test_network_cli.py`.
- **Network doc reconciliation — Spec 1.7 (no design change):** the frozen Network-Aware MS Annotation spec is amended to **Spec 1.7** (2026-10-05). Stage 4 now states normatively that an uninterpretable Δmass emits **no edge** (the `"unassigned"` literal stays reserved in the schema but is never produced), matching `MassFlow.network.chemical` and `docs/network-data-model.md`; `docs/network-data-model.md` no longer lists "wiring of seeds from the annotation run" as deferred (`MassFlow.network.context.seeds_from_results`, P6.1, implements it); and the `MassFlow.network.context` module docstring is corrected. Docs: `docs/network-aware-annotation-spec.md`, `docs/network-data-model.md`, `docs/CHANGELOG.md`.
- **Golden CSV tests made platform-portable (they failed on Linux):** the byte-exact CSV-digest assertions in `tests/test_library.py::TestGoldenDeterminism` and `tests/test_scientific_validation.py::TestGoldenPipelineRuns` failed on Linux because scores are exported at full float64 precision and macOS (Accelerate) and Linux (OpenBLAS) round the low-order bits differently — identical scientific results, different bytes. Comparison is now **by value**: column order, row counts, categorical/integer fields and matched-peak counts are compared exactly, numeric fields within a tight tolerance (~1e-9), and within a query the exported rows are compared as a set ordered by score then reference (score-tie order is not part of the contract). The SQLite/Zarr equivalence test runs both backends on the same platform (a portable byte-for-byte check). No production output or scientific contract changed; the manifest still records `csv_sha256` for provenance. Docs updated (`docs/multiprocessing.md`, `docs/user-guide/scientific_validation.md`).
- **Worker pool no longer `fork`s (fixes a Linux hang in CI and a latent production risk):** `run_annotation_pipeline` built its `ProcessPoolExecutor` without an explicit start method, so Linux used `fork` while macOS already used `spawn`. Forking a multi-threaded process copies the other threads' lock state into the child while dropping the threads themselves, so a child that needs a lock held at fork time deadlocks forever. That is reachable in practice: under pytest the process accumulates threads (an asyncio event loop and thread-pool workers) from earlier tests — which hung the Ubuntu CI job in `tests/test_provenance.py` for hours — and the streaming server carries a live event loop by design. The pool now pins `multiprocessing.get_context("spawn")` explicitly (`MassFlow.workflow._WORKER_MP_CONTEXT`), matching the benchmarked configuration, with a regression test asserting the start method. See `docs/multiprocessing.md`.
- **`massflow tutorial` produced an unusable dataset (found by the new self-generating smoke gate):** the tutorial generator wrote a `similarity.tolerance_unit` key that does not exist (strict config validation rejected it, so `massflow annotate --config tutorial/tutorial_config.yaml` failed immediately) and used CWD-relative input paths (`tutorial/tutorial_experimental.mgf`) that were double-prefixed under config-relative path resolution (the library/query files could not be found). The generator now emits the same strictly-valid, config-relative paths as the committed fixtures, and `tests/test_cli.py::test_run_tutorial_generates_valid_config` locks the contract by running `massflow tutorial` in a temp directory and asserting the emitted config passes strict validation with correctly resolved inputs. The new `make smoke` target runs the generator in a throwaway directory and annotates the result, without touching the committed `tutorial/` fixtures.
- **Documentation reconciliation — stale FBMN / GraphML claims (N-8):** `AGENTS.md` no longer lists FBMN (`consensus_spectra.mgf`) as a **stable output** (§5.4) nor "GraphML networking" as an **implemented experimental** feature (§6.1, §2.5); both now point at `docs/CAPABILITY_MATRIX.md` §2.4 and the actually-implemented `massflow network` surface. `CONTRIBUTING.md` and `docs/index.md` were aligned the same way, and the roadmap's "Networking" heading (which actually described gRPC streaming) was retitled "Streaming" to remove the naming collision.
- **Ionisation-mode gate misread adduct notation (found reviewing #72):** the compatibility gate in `SimilarityEngine.search` classified a candidate pair as "opposite ionisation modes" whenever the two adduct strings each contained both a `+` and a `-` character, so `[M+HCOO]-` vs `[M-H]-` (both negative) and `[M+H-H2O]+` vs `[M+H]+` (both positive) were silently discarded before scoring. The #72 registry expansion grew the dual-sign population from 3 to 7 of 22 entries, making the latent defect substantially more reachable. Ionisation mode is now read from the resolved adduct charge via the new `MassFlow.cheminformatics.adduct_charge`; notation the registry cannot resolve falls back to its trailing charge token and otherwise still means "no opinion", so only genuinely opposite-mode pairs are dropped. Tests: `tests/test_similarity_internals.py`, `tests/test_adduct_registry.py`.
- **Adduct-notation rejections at ingestion (issue #72) — a registry-coverage gap, not a mass error:** real `.msp`/`.mgf` libraries write the same ion in many ways, and every spelling the strict 5 ppm gate could not resolve flagged an otherwise correct spectrum `is_physically_valid = False`, quarantining it at ingestion. Canonical strings such as `[M+H]+` already resolved; `M+H`, `M+Na`, `[M+H]1+`, `[m+h]+`, and alias chemistry such as `[M+FA-H]-` / `M+OAc` did not, and adducts common in public libraries (`[M+2Na-H]+`, `[M+TFA-H]-`, `[M+H-H2O]+`, `[M-2H]2-`, …) were absent from the registry entirely. Notation is now canonicalised before lookup and the registry covers those adducts (the legacy `[M+FA-H]-` spelling resolves to its canonical `[M+HCOO]-` key). Gate semantics are unchanged: an unresolvable adduct still fails closed and the 5 ppm tolerance is untouched. Tests: `tests/test_adduct_registry.py`.
- **Zero decoy hits on real-world runs (`fdr_uncalibrated`) — root cause, diagnostics, and honest labeling (issue #68):** an investigation on the MASSBANK benchmark store showed that the decoy null is empty by *geometry*, not because a decoy is lost: `generate_decoys` displaces every fragment by `±processing.decoy_mz_shift_da` (1.0 Da default), i.e. 50× the 0.02 Da MS2 scoring tolerance, so decoys can never satisfy the positional `min_matched_peaks`/`min_score` gates (measured: 0 decoy rows out of 195,737 scored decoy pairs vs 16,264 target rows in the recorded modified-cosine run). The 5 ppm/MS1 precursor gate is *not* involved — decoys preserve `precursor_mz` bit-for-bit and pass the same window as their targets (verified in Da and 5 ppm modes). Decoys are now **faithful null objects** (they keep their source's complete peak list — the baseline filter only selects which intensities are permuted — so a decoy is never systematically less matchable than the library spectrum it stands in for), and the empty-null state is diagnosable and honest: `SimilarityEngine.decoy_diagnostics` reports `n_decoy_pairs_scored`, `best_decoy_score`, `n_decoy_scores_above_min_score`/`above_gates`, `n_decoy_hits` and `decoy_null_empty` for the whole (chunk-aggregated) search; the engine flags `decoy_null_empty`, the workflow flags `fdr_uncalibrated` and its warning now carries the measured best decoy score; the engine warns when `decoy_mz_shift_da` is *below* the MS2 tolerance (near-copy decoys inflate the null and reject genuine annotations); and rows of an uncalibrated run are exported with `Annotation_Status: Uncalibrated` instead of `Matched`/`Putative`, so a score-filtered candidate list can never be read as an FDR-controlled result. No production threshold, precursor gate, or q-value formula was changed. Tests: `tests/test_decoy_competition_path.py`; docs: `docs/user-guide/scoring_logic.md` (§5.1), `docs/user-guide/results.md`.
- **Unified storage backend interface (storage audit):** `MassFlow.storage.SpectralStore` is now the single backend interface consumed by every workflow — annotation workers, CLI database commands, and the streaming server. It supports everything the annotation engine needs: metadata lookup (`metadata_query`, now also implemented on the SQLite backend), precursor-range filtering (`get_precursor_mz_range`, `precursor_mz` metadata queries), sequential iteration (`get_spectra`/`iter_spectra`), batched access (`batch_get_arrays`, `iter_processed_chunks`), spectrum count, and `backend_provenance()`. The duplicate `LibraryBackend` protocol and `StoreLibraryBackend` wrapper were removed; `open_library` returns a `SpectralStore`; the raw-file fallback is now `RawFileLibraryStore`, a read-only `SpectralStore` adapter (writes rejected explicitly); the streaming server loads its reference library through the same interface. `storage_backend` now has one unambiguous meaning: `prepare_library` builds the library store in the configured backend (`<stem>_library.db` for sqlite/hybrid, `<stem>_library.zarr` for zarr), the store cache key includes the backend, and run provenance records the EFFECTIVE backend actually used. Contract tests (`tests/test_storage_contract.py`) run the same search against SQLite, Zarr, and hybrid libraries and assert identical spectrum IDs, precursor metadata, peak arrays, similarity scores, and ranking order.
- **Pytest discovery & test groups (repo audit):** explicit discovery is configured (`testpaths = ["tests"]`) so scratch/exploratory tests under `scripts/experiments/` are never collected, and the default `pytest` selection runs exactly the release suite (unit + integration + scientific-validation) while excluding `benchmark`, `slow`, and `optional` tests unless requested. Markers are registered and `--strict-markers` is enforced; `tests/benchmarks/` is benchmark-marked via conftest; scientific-validation files carry a module-level `scientific` marker; optional-dependency tests (hnswlib-backed HNSW) are marked `optional` and properly skip when the extra is missing (the previously failing `test_hnsw_parameters_flow_to_index` no longer breaks local runs). CI now verifies formatting (`ruff format --check`), linting, type checking, the release suite with coverage, the scientific group explicitly, and the optional group explicitly, on the declared supported matrix (Python 3.13 × Linux/macOS, declared via trove classifiers). Benchmarks and slow tests never run in CI and cannot block ordinary runs. See `CONTRIBUTING.md` (Tests) and `.github/workflows/ci.yml`.
- **Reproducible packaging (release audit):** `uv.lock` is now explicitly committed (it was tracked but listed in `.gitignore`). The supported Python version is explicit (`requires-python = ">=3.13,<3.14"`, `.python-version` = 3.13); the stale `[project.optional-dependencies] dev` extra was removed (the dev tooling lives in `[dependency-groups] dev`); CI installs strictly from the lockfile (`uv sync --frozen`) and fails when the lockfile is out of date (`uv lock --check`). Two people checking out the same commit can recreate the same environment with `uv sync --frozen`. See `docs/getting-started/installation.md` (Reproducible Environments).
- **First-class run provenance:** every completed annotation run now writes `run_provenance.json` (counter-suffixed per run) recording: MassFlow version, git SHA + dirty flag, Python version/implementation/platform, resolved dependency versions, the committed lockfile SHA-256, the normalized configuration with its digest, engine/processing configuration, storage backend, decoy seed and parameters, per-input-file SHA-256 hashes, the reference-library digest, run start/completion timestamps, and the completion summary (per-status counts, aggregated warnings, degraded-mode flags, failed files). The record is written before per-file processing begins and finalized afterwards; it is deterministic except for the explicitly time-varying fields (`run_started_at`, `completed_at`). See `docs/user-guide/results.md` (Run-Level Provenance) and `tests/test_provenance.py`.
- **Zarr peak fidelity (storage audit):** storing a spectrum can no longer silently change its scientific data. The tensor layout previously truncated over-capacity spectra to the first `max_peaks_per_spectrum` peaks with no warning or record. Now: (1) over-capacity spectra raise `PeakCapacityError` by default (`peak_reduction="none"`), rejecting the batch atomically; (2) an explicit `peak_reduction="topN"` policy retains the N **most intense** peaks deterministically and records the reduction in per-spectrum provenance (`extra_metadata.peak_reduction`), which round-trips into reconstructed spectra; (3) the layout, capacity, and reduction policy are persisted in a store manifest and validated on every open, so a store reopened with mismatched parameters fails loudly instead of misreading its data; (4) legacy pre-manifest stores are inferred from their arrays and may only be opened with the strict policy. The flat layout (and the hybrid `ZarrPeakArrayStore`) store every peak exactly with no capacity. See `tests/test_zarr_store.py` (`TestPeakFidelity`, `TestTopNReduction`, `TestStoreManifest`, `TestSimilarityEquivalenceAcrossStorage`).
- **Streaming server security (audit):** the gRPC streaming server previously bound `[::]` (all interfaces) with plaintext transport and an unauthenticated control plane that could replace the configuration and load arbitrary server-side library paths mid-stream. Now: (1) the default bind is loopback-only (`127.0.0.1`); (2) non-loopback binds require TLS (`--tls-cert`/`--tls-key`) or an explicit `--allow-insecure-remote` override that emits a prominent warning and an audit-log entry; (3) TLS is supported via `grpc.ssl_server_credentials`; (4) every control-plane operation requires the admin token (`--admin-token` / `MASSFLOW_ADMIN_TOKEN`, `authorization: Bearer <token>` metadata, constant-time comparison) and the control plane is **disabled entirely** when no token is configured; (5) `SET_CONFIG`/`LOAD_LIBRARY` additionally require `--allow-remote-control` and apply **transactionally** (a failed reload leaves the running state intact); (6) every administrative action is audit-logged to `massflow.streaming.security` with peer, command, and outcome; (7) message size, control-payload (1 MiB), and per-packet peak-count limits are enforced, and queue-rejected spectra always receive an explicit error response (no silent drops); (8) a single shared consumer routes responses strictly back to the owning connection — annotations can no longer leak across concurrent clients (the previous per-connection consumers crossed responses between clients). See `docs/api/queue.md` and `tests/test_streaming_security.py`.
- **Tooling deprecation & supply-chain hygiene:** `asyncio_default_fixture_loop_scope = "function"` is now set explicitly in `pyproject.toml`, silencing the pytest-asyncio deprecation warning about the future default change (all async fixtures in the suite are function-scoped, so behavior is unchanged). The docs site no longer loads `polyfill.io` (`mkdocs.yml`) — the CDN changed ownership in 2024 and is a known supply-chain risk, and MathJax 3 requires no polyfills on supported browsers.
- **Docs accuracy (capability-audit follow-up):** `serve` is documented as the deprecated alias of `stream-server` in the CLI/server guides (examples now use `stream-server`); the README quickstart YAML no longer enables `hnsw_enabled` under `modified_cosine` (an invalid combination under strict config validation); the unimplemented FBMN export and GraphML/`massflow visualize` workflows are explicitly marked as **not shipped** in `docs/user-guide/results.md`, `docs/user-guide/annotation.md`, `docs/user-guide/configuration.md`, and `.github/copilot-instructions.md` (matching `docs/CAPABILITY_MATRIX.md` C-4/C-5); `MassFlow.library` and `MassFlow.ml_client` were added to `docs/api_reference.md`; the `workflow` config section no longer claims unimplemented toggles; the ML satellite example README warns that its reference servers are unauthenticated demos (loopback or TLS-terminated reverse proxy recommended).

## [0.1.0] - 2026-05-10
### Added
- **Formal Data Model:** Implemented Pydantic-based validation for all spectral metadata.
- **SQLite Backend:** Added `massflow db build` to compile `.msp`/`.mgf` libraries into high-performance relational databases.
- **Flexible Validation:** Added graceful fallbacks for in-house libraries lacking structural (SMILES) data.
- **Small Library Support:** Introduced empirical p-value calculations as an alternative to target-decoy FDR for small datasets.
- **CLI Suite:** Finalized `init`, `db`, and `annotate` command structure.

### Changed
- Refactored `SimilarityEngine` to use a factory pattern for easier algorithm swapping.
- Optimized isotopic envelope generation to use vectorized NumPy operations.
- Updated `matchms` filtering pipeline for stricter precursor mass consistency.

### Fixed
- Resolved memory exhaustion when loading large (>2GB) MSP files.
- Fixed floating-point precision errors in cosine similarity scoring.
