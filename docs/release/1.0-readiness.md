# MassFlow 1.0 scope and release decision

**Decision: NO-GO for an official 1.0 release on inspected main `ffef50b`.**
This is a proposed release scope, not a version bump, release approval or claim of
chemical validation. Inspection date: 2026-10-22. Human review remains mandatory.

The smallest useful release is a local, configuration-driven **candidate retrieval
and review tool**: open-format MS/MS input, deterministic processing, classical
cosine/modified-cosine search, source-spectrum traceability, SQLite libraries and
inspectable CSV results. It must be possible to install and use this path without
TUI, learned models, approximate indexing, streaming or molecular networking.

## Feature dispositions

A = stable/supported after gates pass; B = included with explicit limitations;
C = experimental/opt-in; D = deferred; E = remove or replace the stated contract.
These are recommendations for 1.0, not assertions that current main meets them.

| Major feature | Disposition | Support boundary and critical path |
| --- | --- | --- |
| CLI `init`, `annotate`, configuration validation | A | Supported primary interface; documented examples and installed-wheel smoke must work |
| Metadata/peak processing and float64 spectra | A | Exact behavior/config/units recorded; repair, missingness and fragment-window corrections qualified together |
| Open MGF/MSP/mzML/mzXML parsing | A | Explicit malformed-record/failure accounting; no vendor raw conversion promise |
| SQLite build/inspect/search | A | New stores carry unique source-record identity, lineage and processing semantics |
| SQLite append/merge and legacy-store migration | B | Duplicate IDs and obsolete processing cannot be silently reused; explicit new-path rebuild required. Defer unsafe combinations rather than making them a launch prerequisite |
| Classical cosine | A | Spectral similarity/candidate ranking within declared filters, not confirmed identity |
| Modified cosine | B | Analogue/shift matching can rank different structures; mixed-frame recall fix required or acceleration disabled |
| Source attribution/provenance | A | Chemical identity distinct from acquisition ID; every candidate resolves to a source spectrum. Missing historical provenance cannot be reconstructed by a sidecar |
| Numerical q/p reporting | B | Explicit estimated_uncalibrated/unavailable/invalid semantics, method/counts/limitations; no calibrated-FDR claim |
| Empirical FDR control / confirmed chemical identification | D | Requires independent known-truth evidence in a declared domain; neither score thresholds nor passing tests establish it |
| CSV export and failure/provenance sidecars | A | Selected/rejected/searched/candidate outcomes remain distinguishable; confidence unavailable is never zero |
| FBMN paired export | D | Not shipped on inspected main despite older governance claims; do not promise it for 1.0 |
| mzTab-M export | B | Treat as an implemented interchange surface; validate standards compliance independently before claiming full mzTab-M conformance |
| TUI and interactive configuration wizard | C | Optional convenience, never a prerequisite to run the stable CLI; candidate display is not identity confirmation |
| Numba modified-cosine pruning | C | Exclude from launch critical path by disabling until exact-candidate agreement is qualified on the combined candidate |
| HNSW approximate candidate search | C | Default off; independent recall/parameter evidence required; no instant/sublinear completeness promise |
| Zarr/hybrid stores | C | Optional backend behavior, cache/migration equivalence separately tested; SQLite is sufficient for 1.0 |
| Spec2Vec/MS2DeepScore, consensus/cascade/routing | C | Optional learned/meta methods; training overlap, score scales and confidence transfer unvalidated |
| Remote ML service / streaming gRPC | D | Experimental API/schema/confidence contracts excluded from the supported launch path |
| Spectral networking, propagation and graph export | D | Separate unmerged stack; context hypotheses add no independent identification/FDR evidence |
| Watch/automated ingestion and TUI browser | C | Opt-in convenience with explicit failure/provenance handling |
| ProteoWizard wrapper / vendor conversion | D | External conversion tool; supported core consumes open files and rejects vendor raw |
| Claims of calibrated structural annotation, universal 5-ppm soundness, guaranteed full traceability or instantaneous search | E | Replace with the bounded behaviors and limitations above |

## Measured diagnostic evidence and interpretation

The [frozen MassBank report](https://github.com/janusson/MassFlow/blob/codex/experimental-validation-benchmark/benchmarks/massbank-v1/RESULTS.md)
records 100 attempted queries per arm, 99 primary eligible after one potential
single-peak leakage flag, and eight minimum-peak processing drops retained in
accounting. Present-library exact full-key top-one is 52/99 for cosine and 27/99
for modified cosine. With 50 truths absent, incorrect candidate assignment is
2/50 and 46/50, respectively. Keeping the flagged query gives present top-one
52/100 and 27/100; exclusions are not hidden. Both downloads share one archive
hash, and all metric dictionaries reproduce across diagnostic runs.

Zero cosine decoys mean confidence unavailable; one modified-cosine decoy means
estimated_uncalibrated. The mixed modified-cosine observed wrong-call fraction at
legacy q<=0.05 is 75/91, a descriptive cohort FDP. Query/reference source labels,
raw-lineage limits, different candidate domains and unmerged fixes prevent a
universal performance or calibration claim. Do not promote these results into
validated FDR control or tune this known test panel. Full combined-version review,
per-pair gate instrumentation and independent calibration uncertainty remain pending.

## Ranked remaining blockers

1. **Scientific meaning and provenance:** integrate/review #103–#107 and reconcile
   #101 with the fragment contract; eliminate ambiguous source IDs and incorrect
   candidate pruning. Disable optional paths not qualified for launch.
2. **Confidence transparency:** explicit state/method/scope, missing versus zero,
   no validated-FDR or confirmed-identity wording. Empty and nonempty decoy nulls
   do not establish empirical error control.
3. **Combined-version reproducibility:** select one clean candidate, reconcile
   processing revisions, rebuild managed caches and external stores into new paths,
   rerun all gates and the frozen measured-data benchmark on that exact version.
4. **Install/artifact policy:** resolve transitive RDKit disclosure/support;
   qualify wheels and sdists outside the checkout and gate official publication.
5. **User-facing contract:** CLI-first quickstart, precise Python support, source
   attribution/units/missingness, honest standards/performance limits and migration
   instructions. Explicitly exclude deferred features from launch acceptance.

Calibration research is a blocker to a **calibrated-FDR claim**, not an excuse to
ship misleading confidence or an unavoidable prerequisite to a transparent
candidate-ranking tool with explicit unvalidated estimates. If a desired product
claim exceeds the evidence, defer that claim instead of inventing an accuracy cutoff.

## Suggested PR and manual integration sequence

1. Review the independent correctness PRs #103/#104/#105/#106/#107 and the #101
   contract conflict. Do not mechanically merge this list; combine/rebase in a
   temporary candidate branch and resolve shared processing semantics explicitly.
2. Review/integrate [confidence PR #110](https://github.com/janusson/MassFlow/pull/110) after its full checks. Preserve
   legacy numerical diagnostics only with explicit availability/migration guidance;
   do not treat new state fields as calibration evidence.
3. Review [validation/benchmark PR #111](https://github.com/janusson/MassFlow/pull/111). Freeze
   dataset/config/harness/application identities and publish negative outcomes too.
4. Reconcile the capability matrix and optional/deferred feature docs with this
   scope. Prefer excluding networking, streaming, learned methods and approximate
   indexing from the supported path over expanding launch implementation.
5. Resolve dependency and release-artifact qualification issues. Build/install both
   artifacts, run core CLI and library workflows, and record exact artifact hashes.
6. On a clean combined candidate rerun full coverage/lint/type/docs, installed-wheel
   smoke, source-record migration checks and frozen benchmark. Review all failure,
   exclusion, empty-null and numerical-difference reports before a go decision.
7. Only after human approval prepare a separate version/changelog/release-candidate
   change. This work does not bump versions, create tags, merge or publish.

Processing revisions from #103/#105/#107 must not alias: use a new coherent
revision on the combined implementation. Externally supplied native stores are
not automatically reprocessed. Rebuild from raw sources to a **new destination**,
inspect record counts/IDs/metadata and only then switch library_path. Do not append
corrected records into an old invalid store and call that migration.

## Scientific terminology and applicability

- **Spectral similarity:** agreement under a stated peak assignment/tolerance.
- **Candidate ranking:** ordering possible library structures; repeated acquisition
  records must not fill a distinct-structure top-five metric.
- **Putative annotation:** a candidate supported by the stated evidence and known
  limitations, not a confirmed identity.
- **Confirmed identification:** requires application-appropriate independent
  experimental confirmation; a library score/q column alone is insufficient.

The initial measured benchmark addresses deposited positive-mode, singly protonated
ESI MS2 standards under fixed preprocessing/tolerances. Full-key and connectivity
endpoints are distinct. It does not establish stereo selectivity, matrix unknown
identification, extraction recovery, negative/multiple-charge/adduct performance,
concentration, detection limits or calibrated FDR. Original standard labels and
acquisition independence must retain their actual evidence tier. Numerical tests
prove software invariants; measured retrieval results support only their frozen
cohort and conditions.
