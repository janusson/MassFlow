# Similarity Engines

The `MassFlow.similarity` module encapsulates the logic for comparing mass
spectra. It supports standard algorithms (cosine, modified cosine) and
machine-learning models (Spec2Vec, MS2DeepScore), as well as meta-engines
that combine them (consensus, cascade) and triage-based routing.

## Decoupled ML architecture (massflow-ml boundary)

MassFlow keeps the core package lightweight: **PyTorch, Gensim, spec2vec, and
ms2deepscore are never core dependencies**. External ML scoring is provided
through a strict API boundary:

```mermaid
graph TD
    CORE[MassFlow core<br/>similarity.py] --> PROTO[MLEngineProtocol]
    PROTO --> LOCAL[Local engines<br/>Spec2VecEngine / MS2DeepScoreEngine<br/>entry-point registry]
    PROTO --> REMOTE[RemoteMLEngine<br/>ml_client.py]
    REMOTE --> REST[REST JSON<br/>http(s) endpoints]
    REMOTE --> GRPC[gRPC<br/>massflow.v1.ml service]
    CORE --> META[Meta-engines: Consensus / Cascade / MLRouter]
    META --> FALLBACK[Classical fallback<br/>modified_cosine + empirical p-values]
```

### The protocol

- `MLEngineProtocol` (`MassFlow.protocols`) defines the contract every engine
  — local or remote — must implement: `search()`, `batch_score()`,
  `load_model()`.
- Local implementations register through the
  `massflow.similarity_engines` entry-point group (e.g. from the
  `massflow-ml` satellite package) and are discovered at runtime by
  `get_similarity_engine()`.
- All scientific payloads use **float64** arrays; scores and result
  dictionaries follow the shared `SearchResult` structure.

### Remote engines (REST / gRPC)

Configure remote endpoints per algorithm in the YAML config:

```yaml
similarity:
  algorithm: "consensus"
  ml_endpoints:
    spec2vec: "http://ml-host:8080/spec2vec"
    ms2deepscore: "grpc://ml-host:9090"
  ml_request_timeout_seconds: 10.0
  ml_circuit_breaker_threshold: 3
  ml_circuit_breaker_cooldown_seconds: 60.0
```

When an endpoint is configured for an algorithm, scoring is routed to the
remote service (`RemoteMLEngine` in `MassFlow.ml_client`):

- **REST** (`http://`/`https://`) — a JSON contract mirroring the
  `massflow.v1.ml` protobuf messages, using only the Python standard
  library.
- **gRPC** (`grpc://`) — the `MLEngineService` defined in
  `protos/massflow/v1/ml.proto` (stubs generated by
  `scripts/protoc_gen.sh` into `MassFlow.generated`).

### Circuit breaker & graceful fallback

Every remote call is wrapped in a `CircuitBreaker`:

1. After `ml_circuit_breaker_threshold` consecutive failures (timeouts,
   connection errors) the circuit **opens** and subsequent calls fail fast
   — no more paying the network timeout on every batch.
2. After `ml_circuit_breaker_cooldown_seconds` one **half-open** trial call
   is allowed; success closes the circuit.
3. While the circuit is open (or when local heavy dependencies are not
   installed), the orchestrator degrades gracefully:

- `ConsensusEngine` falls back to **modified_cosine** when every
  sub-engine fails or none can be built.
- `CascadeEngine` falls back to **modified_cosine** when no stages exist
  or the first stage fails.
- `MLRouter` reruns failed/timed-out hard batches through the configured
  classical fallback engine.
- The workflow wraps direct engine calls in a final classical safety net,
  and **empirical p-value scoring** is always applied on top of whatever
  results are produced — a failed ML call can never crash the run.
